# site-research: pvzhtbot.com API/client discovery

**Purpose:** Passive, low-volume observation of pvzhtbot.com's existing web
client, to accurately document its API before building a Tampermonkey
userscript. This phase does **not** build automation, bulk actions, or the
plugin system - it only documents observed behavior.

## Scope / rules this project follows

- No guessing, brute-forcing, or fuzzing of endpoints.
- Only requests generated by normal UI actions (by you or, in a later
  controlled turn, by me driving the same browser) are recorded.
- No bulk card operations, no bulk profile edits.
- No credentials, cookies, bearer tokens, or session secrets are ever
  written to disk by these scripts - see `scripts/lib/redact.js`.
- Every capture run is time-boxed and interruptible with Ctrl+C.

## One-time setup (you do this)

```
cd site-research
npm install
npx playwright install chromium   # already done once, safe to re-run
```

## Step 1: Log in once

```
npm run login
```

This opens a real, visible Chromium window using a **persistent profile**
stored in `browser-profile/` (gitignored, local only). Log in to
pvzhtbot.com normally in that window. When you're done, just close the
window (or Ctrl+C in the terminal). Your session is now saved to that
profile directory and will be reused automatically - you should not need
to log in again for future capture runs, unless the site's session
actually expires.

Nothing in this repo ever reads, stores, or transmits your password or
session tokens - you type your login directly into the real site's page.

## Step 2: Run a capture session

```
npm run capture
```

This reuses the saved profile (already logged in), opens
dashboard/card-manager/profile pages, and logs same-site
(`*.pvzhtbot.com`) XHR/fetch/document traffic to a timestamped
`.jsonl` file under `captures/`. Headers and body fields that look like
secrets (cookies, auth headers, tokens, passwords) are redacted before
anything is written.

- **Kill switch:** Ctrl+C at any time stops immediately and flushes the log.
- **Timeouts:** navigation/action timeout 20s each; whole session hard-stops
  after 20 minutes if left unattended.
- **Volume cap:** capture stops recording new events after 500 in one run.

While it's running, interact with the site normally: view your profile,
open the card manager, page through your collection, and - if you want
those flows documented - add or remove a **single** card (not bulk).

## Step 3: Review and document

Capture files land in `captures/*.jsonl` (one JSON object per line: a
`request` or `response` record). These are analyzed to populate:

- `docs/authentication.md`
- `docs/profiles.md`
- `docs/cards.md`
- `docs/api.md` (the consolidated spec)

Each documented behavior is tagged as **confirmed** (seen in a capture),
**inferred** (guessed from frontend code/structure but not directly
observed), or **unknown**.

## Project layout

```
site-research/
├── scripts/
│   ├── login.js          one-time manual login, saves persistent profile
│   ├── capture.js        logs same-site network traffic while you browse
│   └── lib/
│       ├── redact.js         strips secrets from headers/bodies/URLs
│       └── capture-logger.js attaches request/response listeners
├── captures/              *.jsonl network capture logs (gitignored)
├── browser-profile/       persistent Chromium profile/session (gitignored)
├── docs/
│   ├── api.md
│   ├── authentication.md
│   ├── cards.md
│   └── profiles.md
└── README.md
```

## Explicitly out of scope for this phase

- The Tampermonkey userscript's core loader, plugin manager, and plugins.
- Any bulk/automated card or profile operations.
- Any endpoint not actually triggered by a real UI action we observed.
